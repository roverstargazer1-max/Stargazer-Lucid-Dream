# 星空博客的写作、预览与发布

更新日期：2026-10-23。当前 `master` 分支统一构建两个主题：新版在 `/`，旧 Kira 在 `/legacy/`。同一份 Markdown 同时渲染，文章原地址由新版承接；旧版对应地址加上 `/legacy/`。两边的切换入口保留当前文章、归档、标签或页面位置，新版正文阅读窗口内也有入口。

这些是仓库配置与本地输出关系，不代表线上已经切换。V20 模拟文章原型仍独立在 4173；真实博客预览使用 4175。

## 首次运行与日常写作

使用 Node.js `22.19.0`、npm `10.9.3` 和根目录 `package-lock.json`：

```bash
npm ci
npm start
```

打开 [新版主页](http://127.0.0.1:4175/)和 [旧版主页](http://127.0.0.1:4175/legacy/)。`npm run start:starfield`、`npm run server` 为同一入口。

按原来的主题方式写文章：

```bash
npx hexo new post "文章标题"
```

创建命令会使用 `scaffolds/post.md`，预填副标题、标签、分类、封面、窄屏封面、文章关联、星空配置与摘要字段，并在每组字段旁保留中文注释和示例。标题和日期自动填写；封面默认空字符串，关联/标签/分类默认空列表，星空默认 `rank: ordinary`、`isolated: false`。封面图片和语义关联仍由作者选择，不会自动猜测；保留默认值也能直接写正文并发布。`scripts/post-scaffold.js` 在 Hexo 创建完成后为每个字段补上对应的 YAML 注释；已有文章在预览／构建时补齐。说明直接位于字段上方，不再添加集中提示属性。VS Code 的本项目预览使用 YAML 代码块显示文章头部，因此源码和预览均可查看逐字段注释；注释不进入两套主题发布的正文。完整说明见[字段速查](article-fields.md)。

`starry_excerpt` 留空时，预览／构建会从正文自动提取最多 180 字的新版描述摘要；直接填写则采用手写内容，清空恢复自动。程序识别手写修改并维护 `starry_excerpt_generated`，不用手动切换。自动摘要会随正文更新，手写摘要会保留。身份、原链接、星位与星表号也在预览/构建时生成，不是在新建命令执行时生成。封面用于旧 Kira 列表与文章页，以及新版分享图片元信息；新版星空和正文底图不受它影响。`related` 用于新版文章关联，不改变旧版文章排序。

在 `source/_posts/` 中填写原有 title、date、tags、cover 等字段与 Markdown 正文。原有相对 `../image/` 图片写法继续兼容，两边的 HTML 都映射到各自发布的图片目录；原稿不改。原生 HTML、引用、列表仍走 Hexo 渲染；原 Kira 的 biliplayer、pen 标签由新版复用原实现，写法相同。音乐播放器及其文章、个人页和归档入口已从两个主题移除。

服务已运行时，修改文章、配置或主题后执行：

```bash
npm run preview:starfield
```

随后刷新浏览器。该命令自动完成准备、保存与两个主题的生成，无须先执行额外准备命令；服务没有文件监听。服务未运行则直接 `npm start`，停止按 `Ctrl+C`。

文章身份、原链接、描述与新星位自动保存到 Front-matter 和 `source/_data/starry-layout.json`；永久星表号只保存到布局中对应文章的 `catalogNumber`，不要求作者手填 `ID`。首次登记按发表时间、内部身份分配 `SLD-0001` 起的编号，以后从全部已保存记录的最大号继续追加；补发旧日期不会重排已有编号。删除文章后仍保留其布局登记，编号不复用，恢复同一身份的文章继续用原号。已有星位也保持稳定，自动字段不要手工修改。

日常先本地预览，将更新后的文章与 `source/_data/starry-layout.json` 一起提交，才能让编号在后续新增、删除和更名时延续。新文章只填原字段也能在 Netlify 构建：身份由文件路径确定，相同源内容与已有登记可复现；托管构建中生成的文件不会自动写回 GitHub，不能代替提交登记结果。

草稿放在 `source/_drafts/`，正常构建不发布。用 `npx hexo publish "草稿文件名"` 发布后，两边下一次构建同时加入该文章。

## 窗边手记

新建手记或日记，用一个简单命令：

```bash
npm run diary
```

它在 `source/_journal/` 自动创建 Markdown，填写当前日期、时间及可选字段，并保留中文说明。打开命令输出的文件，在最后一个 `---` 后直接写正文即可。正文留空时不会在博客显示。默认按站点时区填写时间，未配置时使用 Asia/Singapore；同一分钟多次新建自动加序号，不覆盖原文件。

也可以给一个小标题，或创建时直接填写正文：

```bash
npm run diary -- "散步之后"
npm run diary -- --content "今天想留下的几句话。"
```

习惯原生新建文章的写法时，也支持：

```bash
npx hexo new journal "散步之后"
npx hexo new diary "睡前日记"
```

可选 `--date "2026-09-22"` 补写只有日期的记录，`--date "2026-09-17 21:01"` 指定时间，`--draft` 新建未公开草稿。多行 Markdown 可从已有文件导入：`cat saved-note.md | npm run diary -- --stdin`。直接命令 `npx hexo journal` 与 npm 入口相同；`npx hexo help journal` 查看选项。原来的 `new post`、`new page`、`new draft` 用法沿用。

手记模板位于 `scaffolds/journal.md`，只包含日期、可选标题和公开状态；不要求封面、标签或星位。日常记录一则一个 Markdown 文件，不进入文章星、文章检索或 Kira 的文章列表；也可以手动创建：

```markdown
---
date: 2026-10-23
---

今天想留下的几句话。
```

日期只精确到天时保留原样；若记下了时间，可写 `date: 2026-10-23 21:01`。这些时间按写下的当地日期展示，不经浏览器时区换算。月份和日子由新到旧排列，同一天的记录按填写的时间顺排。可选 `title` 作为小标题，`published: false` 作为未公开记录；未公开正文不会渲染或复制到发布目录。文件名决定这则手记的独立链接，分享之后尽量保留文件名。

执行平常的 `npm run preview:starfield` 后刷新页面即可。桌上的本子打开手记；本子被画面裁切时显示左下角书签。星空右下角也有“手记”入口。开合沿入口方向展开和收回，正文保持连续阅读；左右箭头翻到相邻有记录的月份，“翻阅月份”可直接选择年月。关闭后保留本次月份、滚动位置和进入前的场景；减少动态效果及 `?motion=soft` 使用短淡入淡出。点击外侧或按 Escape 合上；年月菜单展开时，第一次 Escape 先收起菜单。

`/journal/` 提供独立可读的页面和每则记录的锚点，直接打开、刷新及关闭 JavaScript 均可阅读。新版作为备用主题时地址自动变为 `/starfield/journal/`；手记没有旧版对应页面，其独立页提供“回到窗边”。

阅读底图取自当前星空截图的云层，桌面和手机分别裁切，随正文滚动并纵向无缝重复；没有自动漂移动画。每则记录旁的独立链接箭头已移除，已分享的锚点地址继续有效。两张显示素材保存在主题的 `source/images/journal/`；更换星空截图后可用 `python3 themes/stargazer-starfield/tools/prepare-journal-sky.py` 重建。该维护脚本需要 Pillow，生成的 WebP 已保存，平常写作、预览和生产构建不需要 Python。

手记图片默认只显示“查看图片”，点击后才请求图片并在正文原位置展开；可再次点击收起，重新展开复用已加载的图片，失败时可重试。原有 Markdown 图片写法沿用，正文与图片源文件不变；关闭 JavaScript 时提供主动查看原图的普通链接。向下阅读后，右侧留白出现小型“回到顶部”按钮，返回当前月份的开头；独立页返回页面顶部。完整动效下平滑滚回，轻过渡与系统减少动态效果时直接返回。

已从作者 Obsidian 的“日记？小记？”迁入 13 则真实手记，日期范围为 2026-06-02 至 2026-10-09；标有“留存不发”的一篇未迁入。正文原字保留，两张内嵌图片原样复制到 `source/image/journal/`；文件名中的 `·` 识别为时间分隔符，10 月 9 日正文开头的 `00:47` 移到时间栏，只显示一次，没有时间的记录只显示日期。Obsidian 原文件未修改。逐篇来源与一致性核对见[迁入记录](../../.scratch/starry-blog/evidence/obsidian-journal-import-20261023/README.md)。

只有在没有已公开手记时，**统一本地预览**才会使用标明“本地体验 · 以下文字为虚构示例”的演示记录，便于体验年月与同日多则。存在真实记录时自动使用真实内容；正式 `npm run build` / `npm run netlify` 始终排除示例，尚无内容时显示等待第一句话的空白页。演示数据位于独立模块的 `components/journal/preview.json`，不在可直接发布的 `source/` 中。程序化写入与读取的接口见[手记模块说明](../../components/journal/README.md)。

## 友链

穿过窗户后，星空穹顶稍下方的高空有一枚蓝紫色通信卫星，作为友链入口。桌面平视时需向上探索才能发现，手机纵向视野仍可在上方看到。它的位置和图像大小跟随探索镜头投影，放大时变大、缩小时变小；仅点击范围保留 44px 最小尺寸。移出画面时由屏幕边缘自然裁切，完全离开后再隐藏；房间及星空右下角的固定友链按钮已移除。悬停／键盘聚焦卫星时显示“远方的信号／友链”，点击后在当前场景展开朋友列表；手机点按直接打开。关闭按钮、Escape 或点击面板外侧均可返回原来的星空和键盘焦点。手机使用可滚动的单栏列表；点选朋友在新窗口访问。轻过渡与系统减少动态效果使用短淡入淡出，并取消卫星位移和循环信号。

名称、链接、头像与简介仍在 `_config.hexo-theme-kira.yml` 的 `friends` 中维护，新旧主题共用，修改后重新预览即可。`/pages/friends/` 是同样风格的独立页面，支持直接打开及无脚本阅读；新版位于备用路径时自动使用 `/starfield/pages/friends/`。

当前友链头像均保存在 `source/image/友链/`，由本站提供；更新头像时可将新图片放在这里，再修改对应的 `avatar` 路径，减少访客对第三方图片服务器的请求。

## 可选文章配置

搜索栏右侧的放大镜沿用原图，悬停、键盘聚焦和按下时只有透明图标产生反馈，后方蓝色纹理保持静止；静止时显示完整原搜索栏。减少动态效果时取消图标缩放，搜索与按钮点击范围不变。

新版星空左下角的蓝紫星盘打开检索页，盘面、轴心与指针从 `assets/蓝紫星盘.png` 分层裁切，只有原固定指针占位叠放局部修补图。盘面固定，指针随用户视角的水平方向实时转动；拖动、方向键及自动转向同步，俯仰和缩放保持水平方位。当前 UI 严格以 `assets/检索页/检索页v3.png` 为准，使用 `assets/检索页/v3/` 中的工程导出素材与原稿合成色；桌面统一按原稿坐标缩放，标题在圆图上方居中，搜索／筛选／索引保持 v3 间距与颜色。打开时先展示左侧星图区和右上箭头，在入场后段尚未停稳时自动向右展开 INDEX、退出按钮及索引，动效重叠衔接；点击箭头可手动收起或再次展开，圆图尺寸保持稳定；收起箭头朝左下，展开保留原方向，开合角度相差 90°。手机索引排在圆图下方；短横屏可在图面内滚动查看完整圆图。打开和退出共用 READ 阅读窗口的聚焦淡入淡出，四周保留主页，检索背景模糊已减至 1.2px；减少动态效果时采用短暂无模糊淡入淡出。点击外侧或按 Escape 也可退出。关键词可查标题、标签、正文及 `SLD-0001` 形式的星表号。年份自动读取实际文章，星等仍为 1.0／2.5／4.0；重复点击同一选项取消筛选，清除条件不会收起索引。筛选黑底、边线与数字使用 v3 原稿素材，没有文章的 2024 不显示，选中状态以细线标记。标题直接阅读，关闭文章后回到本次检索条件与位置。方位小星图已按最新反馈移除，探索时也不会出现。无须额外维护检索数据，预览与构建自动生成；草稿不进入索引。

不填下面的字段也能发布。文章关系引用**文件名，不含 .md**，每对只写一次，自动双向；理由选填：

```yaml
related:
  - 另一篇文章的文件名
  - post: 第三篇文章的文件名
    reason: 可选的关联理由
star:
  rank: ordinary
  isolated: false
```

`rank` 可选 ordinary、important、treasured，分别对应普通／重要／珍藏的博客星等 4.0／2.5／1.0，未填写时用普通 4.0。观测面板在 `OBS／ID` 标识后显示“星表号＋当前博客星等”，例如 `SLD-0006 · 4.0`；小字复用日期的数字字形。修改 `star.rank` 后，下次预览会更新展示星等，永久星表号、内部身份和文章链接保持不变。组合值由程序生成，不需要另填 `ID`；光色和闪烁没有随本次展示设定调整。

文章星体与光晕已按作者要求统一缩小 35%，检索星图中的文章星点同步缩小，三种星等之间的尺寸比例保持不变。图像缩小不影响点选范围：星空仍为 48px，检索星图仍为 44px。

`isolated: true` 不生成空间探索路径或时间连线，作者明确的关联仍保留。无效关联会提示源文件，不阻止合法文章阅读。标题可改；改文件名时同步改其他文章的 related 引用。标签与距离不会自动成为内容关系。

`starry_excerpt` 用于描述元信息；留空自动提取正文，直接填写则采用手写描述，不需要修改 `starry_excerpt_generated`。点星后仍显示既有日期观测面板，不展示长摘要。其余星空交互和文章视觉沿用当前已确认设计。

文章文末自动显示“上一篇／下一篇”、标题及日期，按全站已发表文章的发表时间排序：上一篇更早，下一篇更晚，同一时间按内部文章身份稳定排序，不受置顶、更新时间、标签或检索筛选影响。首尾只显示存在的方向，无须新增写作字段。点击在当前阅读窗口从头打开相邻文章；浏览器前进后退可切换已读过的文章，关闭窗口返回进入阅读前的星空、清单或检索。正文进度不包含此导航，关闭 JavaScript 时仍可通过普通链接继续阅读。

| 用途 | 命令 | 输出 / 地址 |
| --- | --- | --- |
| 双主题准备与生成 | `npm run preview:starfield` | `.preview/stargazer/`，含 `legacy/` |
| 双主题预览并启动 | `npm start` / `npm run start:starfield` | 4175 |
| 仅提供已有预览 | `npm run serve:starfield` | 4175 |
| 单独旧版预览 | `npm run preview:legacy` 后 `npm run serve:legacy` | `.preview/legacy/`，4176 |
| 旧版监听式开发服务 | `npm run server:legacy` | 4000 |
| 双主题正式构建 | `npm run build` / `npm run build:starfield` / `npm run netlify` | `public/`，含 `legacy/` |
| 只输出旧版用于恢复 | `npm run build:legacy` | `public/`，Kira 在根路径 |
| 自动验证 | `npm test` | 包含双主题与新增普通文章回归 |

`prepare:starfield` 是双主题预览的兼容别名。`generate:starfield` 是仅生成已准备内容的低层命令，会生成没有旧版切换入口的单主题预览；日常请用统一入口。准备与生成共享 `db.json`，不能并发执行；静态服务可以并行。统一构建先在临时目录完成两边，安装新输出前保留旧目录，安装失败会恢复；若恢复也失败，会保留备份并报告路径。`/legacy/` 为备用主题保留，不能给文章或页面配置冲突地址。

若希望旧版重新作为全站默认主页，修改 `_config.yml`：

```yaml
blog:
  default_theme: legacy
```

执行统一构建后，Kira 在 `/`，新版在 `/starfield/`。改回 `starfield` 恢复新版根主页和 `/legacy/`。文章继续在原来的 `source/` 维护。独立历史恢复见 [旧版指南](legacy-blog-recovery.md)。

默认服务只监听 `127.0.0.1`。端口占用可沿用现有服务，或设置 `STARFIELD_PREVIEW_PORT` 后启动；此变量也适用于旧版静态服务。

完整镜头仍为 `scene.motion: full`。当前穿窗约 2.86 秒：房间按原比例推进，同时侧移并转向星空，三者共用一条连续曲线，只在结尾一起减速停稳；天空与文章星沿途连续显示。回屋沿同步反向路径转回窗边并退入屋内。`?motion=soft` 采用 220ms 轻过渡。穿窗与回屋的微小房间模糊默认关闭，以减轻省电模式的合成开销；在 `themes/stargazer-starfield/_config.yml` 将 `scene.passage_blur` 设为 `true` 可恢复。实际持续掉帧会触发背景精度调整，静止、隐藏页面及浏览器固定刷新节奏不会单独触发降级。当前路径与验证见[连续运镜记录](../../.scratch/starry-blog/evidence/continuous-entry-20261012/README.md)，此前省电优化的测量与首次进入峰值见[省电过场记录](../../.scratch/starry-blog/evidence/power-transitions-20261010/README.md)。
