# 展示 ID 由星表号和博客星等组合

作者于 2026-10-11 暂定采用文章星表方案，并明确新增名为 `ID` 的展示字段，其值组合“星表号”和“博客星等”。观测面板中作者截图所示的 `OBS／ID` 标识附近承载这一值；截图只用于指明位置，见 [位置参考](../../.scratch/starry-astronomy/references/obs-id-placement.png)。

组合格式暂定为 `SLD-0006 · 4.0`：`SLD-0006` 是永久星表号，`4.0` 是当前博客星等，显示一位小数。延续基础方案的普通／重要／珍藏星等 4.0／2.5／1.0，当前由文章的 `star.rank` 决定。完整值自动组合，不要求作者逐篇维护另一个手填字符串。未来若采用个体微差或作者覆盖值，展示最终采用的星等，不能始终显示档位基准。完整星表号可用于引用和索引；未来索引中的 `ID` 也遵循同一含义，窄屏可以换行，不省掉星等。

星表号和内部文章身份保持稳定。作者改变星等后，展示 `ID` 随之更新；文章地址、关联、已读与选中状态的身份不变。组合值负责展示，永久引用继续以星表号或内部文章身份识别文章。未来检索完整组合值时，应提取星表号定位，不因输入包含旧星等而失去文章。

这个决定同时保留“可用短号查找文章”和“展示中带有星等”的需求，避免将一个包含可变属性的展示字符串当作永久身份。基础研究与登记／持久化边界见 [文章星表方案](../../.scratch/starry-astronomy/proposal.md)。真实恒星参照、诞生日天空、光色与闪烁调整仍为后续设想，不因本决策自动实施。

2026-10-11 作者进一步授权本轮接入：每篇文章的观测面板在 `OBS／ID` 标识右侧空位显示组合 ID，字号小于日期，复用日期的数字和技术字母 PNG 字形。现有 10 篇文章已按初次发表时间登记 `SLD-0001` 至 `SLD-0010`，号码保存于 `source/_data/starry-layout.json`；后续新增接保存记录的最大号继续编号，包括已删除文章的占号。现有文章均沿用普通档，显示 `4.0`，不由置顶状态推断作者偏好。

状态区分：本地编号、索引数据和观测面板已实现，验证见 [实现记录](../../.scratch/starry-blog/evidence/article-display-id-20261011/README.md)。星图检索、光色／闪烁细化与真实天文彩蛋继续另行设计；本次没有线上发布。正常写作先本地预览并将编号登记结果随文章提交，托管构建生成的登记记录不会自动写回仓库。
