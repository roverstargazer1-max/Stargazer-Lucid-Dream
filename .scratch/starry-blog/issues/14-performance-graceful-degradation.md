# 14：低性能装饰降级与核心体验保持

Status: ready-for-agent
State: open
Category: enhancement

2026-09-30 用户要求按全部任务顺序自主实施并逐票提交，本票据此正式发布。

**What to build:** 设备能力不足时减少装饰星、云细节和微动，访客仍能穿窗、探索和阅读；渲染不可用时保留同址正文。

**Blocked by:** [13：触屏、键盘与放大后的完整浏览](13-mobile-and-accessible-reading.md)。

**依赖理由：** 13 已提供完整设备输入与内容层流程，才能验证降级前后核心操作不受影响。

## Acceptance criteria

- [ ] 低性能呈现减少装饰星、云细节、微动或必要渲染分辨率，不删文章星、关系、内容范围或核心阅读入口。
- [ ] 在降级前后完成穿窗、拖动/缩放、选星、模式切换、阅读和返回，文章身份、地址和历史规则不变。
- [ ] 减少动态偏好与性能降级分别生效，沿用当前已有小交互，不追加新彩蛋。
- [ ] WebGL 无法创建或渲染运行失败时保持/恢复同址静态正文；媒体及正文访问不依赖持续渲染。
- [ ] 以实际前台和设备采样确定可用策略，记录帧调度、加载与内存的可测范围，不以不可比的后台回调宣称固定帧率达标。
- [ ] 配置低性能装饰参数有兼容缺省，正常设备默认视觉保持 V20 基线；设备不可测项目如实保留限制。

## 演示与测试

- 完成演示：触发低性能呈现完成核心浏览，再模拟渲染不可用直接读同址正文。
- 验证边界：对照降级前后公开流程和静态回退，性能报告注明设备与调度条件。
- 验收记录应说明实际操作、环境、结果及证据；未验证设备或平台能力不标记通过。
