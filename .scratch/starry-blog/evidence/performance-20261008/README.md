# 星空站点性能评估与优化 · 2026-10-08

> 测试产物保存规则（2026-10-09）：本记录保留结论、复测代码及摘要；详细报告、逐次 JSON、截图和录像仅在本地归档，相关链接对应本地文件。历史数据仍在原提交中。见[保存约定](../README.md)。

结论：当前站点在本机没有明显的持续卡顿，但图片流量和静止场景的重复工作值得优化。已在本地完成；保留原分辨率、绘制细节、动画时长、文章范围及用户原有的未提交图标修改。

## 测量范围

- 地址：http://127.0.0.1:4175/，当前真实文章新版主题；不代表远程生产站点。
- 环境：Apple M1 / 16 GB，Chromium 149.0.7827.55，无头模式；桌面 1440 × 900、模拟手机 390 × 844，DPR 2。
- 最终自动测试及生产构建另外对齐仓库指定的 Node.js 22.19.0 / npm 10.9.3 验证通过；浏览器测量脚本使用本机 Node.js 25.7.0 调用 Playwright。
- 每个场景连续采样 4 秒，桌面/模拟手机各 3 次，以中位数对照。独立冷上下文，本站预览服务器不启用压缩并要求 no-store。
- 限速场景：下载 200,000 B/s（1.6 Mbps），150 ms 延迟，CPU 4 倍限速；基线与最终版各一次，另一次中间版本复测得到 16.10 秒。
- 主线程占比来自 Chromium TaskDuration 增量/实际采样时间，包含脚本及样式/布局等任务，不等同于系统 CPU 使用率或 GPU 耗时。手机是模拟视口与限速，未使用真实手机硬件。

## 实际改动与画面保证

1. 三张发布场景图改为无损 WebP，尺寸不变。原始 PNG 保存在 V20 原型素材目录；不再重复发布这三份 PNG。
2. 人物剪影仍用 PNG，只将 alpha=0 的隐藏 RGB 清零并重新压缩；从 1,063,205 B 降为 248,138 B。原始工程 PNG 保留。候选 WebP 在浏览器半透明边缘对照中出现微小差异，已放弃采用。
3. 场景纹理提前请求，窗边插图使用高加载优先级。观测素材继续提前准备，避免首次选星时图片迟到。
4. 窗边与阅读原本静止的 Canvas 复用已绘制帧。穿窗、镜头推进、探索、流星、尺寸/可见性变化仍重新绘制；CSS 微光和几何轻跳保持。
5. 状态、hidden 和图例文字只在实际变化时写入。阅读进度改由滚动和 ResizeObserver 更新；晚到图片、字体、播放器及窗口尺寸变化仍计算文末。

四张优化图片均由 Chromium 原生解码、绘制到 Canvas 后逐通道对照，差异全部为 **0**；见 [像素记录](browser-pixels.json) 与 [资源记录](assets.json)。人物剪影仅隐藏 RGB 数据不同，浏览器显示像素一致。

观测素材最初约 1.33 MB（不含几何图形），优化后约 0.51 MB，保持提前加载。未采用显示时才下载整张观测图的做法。

## 行为与内存验证

- 26/26 仓库自动测试通过；准备两次不改变文章或已保存星位，原文章链接、图片、范围、关联和既有音乐配置保持。
- 新版本地生产构建成功，145 个文件；git diff --check 通过。默认生产/Netlify 配置未切换，没有 push 或线上部署。
- 桌面与窄屏：穿窗、选星、观测图片完整加载、阅读、文末 100%、关闭、双模式切换、回窗边均通过；缩至 1000 × 760 / 342 × 740 时正文无横向溢出。
- 实际页面注入一张晚到图片，进度自动从 46%→28%（桌面）、36%→29%（窄屏），证实无需逐帧轮询也能响应正文高度改变。
- 静止阅读时背景重绘从约 60 次/秒降到 0，未变化文字的重复写入从约 120 次/秒降到 0；窗边 Canvas 像素在一秒间隔内完全一致，重复重绘同样降到 0。
- 连续开关同一篇阅读窗口 12 次（先热身 3 次，每 4 次强制 GC）：JS 堆从 2.73 MiB 到 3.17 MiB，增量 0.44 MiB；第 8/12 次约 3.18/3.17 MiB，未观察到持续增长。末尾实际 DOM 元素数量与热身后相同（264）。这是有限循环，不能证明无限时长无泄漏。

JS 堆不包含图像解码、Canvas/WebGL/GPU 缓冲。为保持原分辨率和视觉，本次没有削减这些缓冲尺寸；节省的是传输/静态输出体积、重复绘制和 DOM 分配。第三方媒体既有播放失败仍可出现，正文可正常阅读，未把媒体成功播放列为本次通过项。
