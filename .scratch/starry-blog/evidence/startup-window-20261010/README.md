# 首屏窗景连续性（2026-10-10）

作者观察到旧版切到新版后，原插画窗景先出现，再被实时星空覆盖。本地初始化延迟 5 秒后重复复现：房间图已可见，其遮罩由 `none` 在一帧内切成窗口遮罩；画面没有过渡。直接打开新版也复现，因此与旧页面残留无关。

首页现在预载当前屏幕对应的窗口遮罩，从首屏起使用最终窗口轮廓和深蓝底色；人物、桌面与窗框不变。天空预绘成功后，只有天空 Canvas 用 0.45 秒透明度过渡显现。减少动态时不执行淡入。没有新增图片素材、依赖或 Netlify 配置。

## 实际浏览器验证

使用 Codex 浏览器，桌面 1280 × 720、手机 390 × 844，预览由同一份 `.preview/stargazer` 提供。测试服务器对实际 `app.js` 请求增加 5 秒延迟，并逐帧记录可见房间、遮罩和天空透明度；探针仅注入测试服务器的 HTML，正式输出不包含探针。

- 优化前反馈循环两次失败：可见房间从无遮罩跳为挖空窗口。
- 优化后两种屏幕均通过：加载前后遮罩地址不变，实际观察到天空透明度从 0 经中间值到 1；没有只依赖 CSS 声明判定动画。
- 手机从旧版顶部“新版”入口进入的原操作通过。
- 暂停主模块时，手机仍显示房间前景和稳定窗口底色，窗口入口保持禁用。
- 遮罩请求失败和入口模块请求失败均恢复可读文章清单。
- 桌面穿窗探索、返回窗边通过，返回后的天空透明度为 1。
- Node 22.19.0 / npm 10.9.3：`npm test` 35/35、`npm run netlify` 双主题生产构建及 `git diff --check` 通过。

摘要见 [startup-summary.json](startup-summary.json)。完整逐帧数据和截图保留本地，遵循[产物约定](../README.md)。这是初始化延迟复现，不是限速性能评分；没有验收线上 CDN、真机或本次远程发布。

## 重跑

先生成双主题预览，再启动专用测试服务器：

```bash
npm run preview:starfield
node .scratch/starry-blog/startup-visual-server-20261010.mjs
```

在实际浏览器打开 `http://127.0.0.1:4187/`。服务器自动记录并判定；初始化及淡入完成后，读取 `html` 的 `data-startup-visual-probe` 属性，`verdict` 应为 `PASS`，`fadeObserved` 应为 `true`。`/?probe=pause` 停在首屏；`/?probe=module-failure` 和 `/?probe=mask-failure` 注入失败，应得到 `PASS: readable fallback`。从 `/legacy/` 点击“新版”可覆盖原操作。停止服务器后再使用正常 4175 预览。
