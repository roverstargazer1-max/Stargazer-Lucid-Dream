# 07：双模式探索、移动中断与历史返回

日期：2026-10-01

环境：Windows 本地预览，Codex In-app Browser，`http://127.0.0.1:4175/`；桌面视口约 1123×631，窄屏视口 390×844。浏览器系统偏好 `prefers-reduced-motion: reduce`。
范围：浏览器端到端操作；不是纯逻辑原型测试。

## 验收操作与结果

- 从窗页进入星空，切换关联/时间模式。时间模式按日期和固定文章 ID 排序；切换后同一文章仍被选中，提示明确说明时间相邻不代表作者关联。返回关联模式后只显示实际采用的语义关系线；最终关系配置和生成索引均为空关系。
- 在完整动效查询参数下点选一颗星，移动途中改选另一颗可见星。简介跟随新目标更新，未误开正文；到达后再次点击才进入文章。对选中星附近画布拖动后，简介保留、阅读动作禁用并显示“点星，重新靠近”；键盘回车触发新的靠近，不执行中断前的过期阅读动作。
- 在简介仍打开时点击空白，选中和简介消失，镜头的目标 CSS 坐标保持不变。拖动操作不会被作为空白点击处理。
- 切换模式时，有选中文章则将同一文章作为停靠点；没有选中时使用目标模式默认起点。返回控件回到最近一次自动完成的停靠点并清除当前选择；无历史时禁用。手动移动没有写入额外的逐帧停靠记录。
- 打开《咏史有感》后滚动正文至约 553px，文章层滚动而星空世界的 `scrollLeft` 保持 0。浏览器前进/后退恢复对应文章、简介和 URL；关闭阅读后恢复选中的星与相机。
- 在 390×844 视口中打开长文《梦开始的地方[置顶]》，滚动正文至约 1388px；文章内容滚动时选中星的 CSS 坐标未变，星空世界 `scrollLeft` 仍为 0。关闭后回到星空视图。
- 直接打开长文路由并刷新，滚至文末显示 100% 及“已到文末 · 关联理由已显露”。临时加入两条本地关系 fixture 后，文末理由出现；fixture 随后移除，没有把临时作者关系留在正式数据中。读过的文章关闭后，星的简介可查看采用理由；切到时间模式后仍保留已读状态，同时展示独立的时间说明。
- 暂时移走忽略目录中一篇文章的生成页面，以使关系链接目标返回 404。链接读取失败后保留此前可读文章卡片和根地址 `/`，不把 URL 改成未成功显示的文章；页面仍可操作。失败 fixture 恢复并重新生成预览。此操作验证了阅读前的目标加载失败路径。
- 新标签直达《咏史有感》且此前没有星空历史，关闭阅读后回到根路由并聚焦对应星；随后可通过窗页按钮回到窗口。直达文章默认聚焦位置经视口核对，不会落在简介卡片下方。
- 刷新时间模式的未选中状态后重新进入，应用从关联模式默认起点开始，选择历史清空，返回控件禁用。
