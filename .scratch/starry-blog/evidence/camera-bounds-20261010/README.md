# 星空视角下边界（2026-10-10）

作者要求先提交前述双主题入口、版本切换与首屏连续性改动，然后将探索视角下限上移，山丘最多占画面底部五分之一。前述改动已独立提交为 `9669161`，本次视角调整在其后实现，尚未发布。

自由探索现在根据屏幕比例、缩放和观察位置计算俯仰下限。屏幕从顶端起 80% 高度处的全部视线均保持在山脊最高点之上；渲染器山脊含过渡最高小于 0.045 弧度，约束采用 0.06 弧度作为余量。手机竖屏和缩远时相应抬高下限，自动停靠的观察位置移动也纳入计算。拖动、方向键、滚轮／双指缩放、窗口变化和历史恢复使用同一约束。穿窗平滑接入新下限，返回房间使用原窗景镜头。

## 验证

- Node 22.19.0 / npm 10.9.3：`npm test` 38/38、`npm run netlify` 双主题生产构建通过。
- 数学测试使用实际 `viewRay` 和球面交点检查画面 80% 高度处的 65 列：六种屏幕尺寸、五种缩放、四个方位和三种观察位置全部满足边界；另含极宽屏幕与安全视角幂等检查。
- 10 篇真实文章在关联／时间模式、六种屏幕尺寸下的停靠保持可达：文章星仍在屏幕内且不被预览面板遮挡，停靠后的山丘边界也通过。
- 实际浏览器验证 390 × 844 与 1280 × 720：穿窗、向下方向键、向下拖动、缩远至 0.36 均通过。横向转动后仍通过。
- 手机时间模式自动前往起点、选择低处的《梦开始的地方[置顶]》、显示阅读按钮通过。停靠后由手机尺寸变为桌面尺寸仍通过；返回窗边、再次穿窗通过。
- 浏览器所检查状态的 80% 行最低世界仰角均不低于 0.06 弧度，见 [browser-summary.json](browser-summary.json)。实际截图中的山丘都在底部五分之一以内。浏览器无警告或错误日志。

浏览器验证使用本地专用服务器，在实际渲染时把相机和几何检查结果写入测试页面的 DOM。探针仅由该服务器注入，不进入正常预览或生产输出。截图保留本地，遵循[产物约定](../README.md)。没有验收真机或线上 Netlify 部署。

## 重跑

在仓库根目录、项目指定 Node 环境中执行：

```bash
npm test
npm run netlify
node .scratch/starry-blog/camera-bounds-server-20261010.mjs
```

在实际浏览器打开 `http://127.0.0.1:4188/`，分别以手机和桌面尺寸进入星空，向下拖动或按方向键、缩远、切换时间模式并选择文章。读取 `html` 的 `data-camera-bounds-probe` 属性：星空稳定状态的 `terrainBudgetPass` 应为 `true`，`minimumElevation` 应不低于 0.06（允许浮点误差）。房间和穿窗中的过渡帧不适用自由探索下限。停止专用服务器后使用正常 4175 预览。
