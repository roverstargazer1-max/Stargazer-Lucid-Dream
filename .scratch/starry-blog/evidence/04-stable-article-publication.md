## 环境与实现

- Node `v22.19.0`、npm `10.9.3`。默认 `_config.yml` 仍选择 `hexo-theme-kira`；星空预览只写入 Git 忽略的 `.preview/stargazer/`，旧 `public/` 未被改写，其 `public/index.html` SHA-256 仍为 `4ab643fe31baba40eca9be8e856e23c8e6f26fffb1a15d60daa0115962d52a5`。
- `npm run prepare:starfield` 先用 Hexo 载入实际发布集合，再保存稳定文章 ID、原始地址、显式 permalink、摘要和版本 2 布局，最后独立构建预览。准备工具位于仓库根目录，不会被 Hexo 的自动脚本目录递归加载。
- 当前 Hexo 发布集合为 10 篇；没有文章因正文含“草稿”字样而被过滤。10 篇都获得持久 ID 与原始地址。置顶文章 `dream-begins` 保留原有 ID、重要度及 `[4700, 3180, 2290]` 星位；布局同时保留删除文章的记录供恢复。
- 9 篇缺省摘要从正文生成纯文本并带 `starry_excerpt_generated: true`；`dream-begins` 保留人工摘要。作者可删除该标记并编辑摘要以切换为手填。空星座名不阻止发布。
- 所有原文章正文与票据 03 基线逐篇比较，统一 CRLF/LF 后文本完全一致；改动只在 front matter 增加稳定发布元数据。准备命令重复运行后报告 `Prepared 10 published article(s); 0 post file(s) updated.`

## 构建与浏览器验收

- 运行 `npm run prepare:starfield`，成功生成 77 个文件。版本 2 索引包含 10 个唯一身份和唯一原地址，所有静态文章路由均存在，页面文章 ID 与索引/保存布局一致。
- Codex In-app Browser 桌面视口中逐星定位 10 个真实文章目标；每个星均可移入视口并显示为可见。对三篇文章实测选星、停靠后阅读真实正文及关闭返回；另对一篇实测原地址直接打开。多篇文章间切换时标题、摘要和正文都对应当前选择。
- `node --check` 检查准备工具、文章索引生成器和浏览器模块通过；`git diff --check`（按仓库 CRLF 设置）通过。自动化浏览器/临时边界夹具在验收后移除，没有留下临时文章或布局记录。

## 稳定性与边界验收

- 新增文章时自动生成 UUID 风格 ID、原始地址和确定性新位置。临时相关/无关文章、可选星座字段和远距离位置输入不改变既有文章坐标。
- 改标题、日期及源文件名后，既有 ID、星位和最初地址不变；删除后重建保留旧记录，新文章不会占用被删除星位，恢复文章后原 ID/位置/地址复用。
- 相同时间戳文章按稳定 ID 产生可重复排序。重复 ID、重复原地址和损坏的必需位置都会以明确错误终止；托管构建缺少已保存布局时指出缺失数据并提示本地运行 `npm run prepare:starfield`。
- 摘要夹具覆盖 Setext/ATX 标题、普通段落、图片、播放器标签、HTML/Markdown 标记和手填摘要，确认生成摘要仅保留正文纯文本。
- 空文章目录能够生成等待状态首页和空索引；单篇孤立文章可准备和构建；包含 720 个既有穹顶位置的拥挤夹具仍能为新文章生成有效位置并完成构建。
