# 文章星表与观测面板 ID 接入

日期：2026-10-11。作者授权本轮落实已暂定采用的 [组合 ID 决策](../../../../docs/adr/0001-article-display-id.md)，并要求在每篇文章观测面板的 `OBS／ID` 标识右侧空位显示，用小字号、沿用日期的数字字形。本次已完成本地实现和双主题预览，未线上发布。

## 最终行为

- 选中文章时显示 `SLD-0006 · 4.0` 这样的组合 ID；字号约为月日的三成。数字和技术字母直接复用日期面板的 PNG 字形，居中点与小数点分别排布。完整值同时提供给屏幕阅读器。
- 星表号只保存于 `source/_data/starry-layout.json` 的 `articles[id].catalogNumber`。首次按发表时间登记，同一时刻以内在身份消歧；后续从全部保存记录的最大号追加，包括已删除文章的占号。改日期、标题、星等或模式不会重排号码。
- 文章索引输出 `catalogNumber`、`magnitude` 与 `displayId`。普通／重要／珍藏对应 4.0／2.5／1.0，由原有 `star.rank` 决定，不增加作者手填的组合字符串。现有文章都沿用普通档，包括置顶文章。
- 同日换篇和只调整星等都会更新 ID；重复更新相同值不会重建字形，也不重复更新日期。现有文章身份、原地址、星位和关联保持。
- 手机跟随面板同比缩小，完整值留在 READ 装饰线左侧。五位星表号同样保留完整星等，不截断。

正常写作先本地预览，将自动保存的文章与布局登记一起提交；托管构建生成的记录不会自动写回仓库。检索界面、光色／闪烁细化和真实天文彩蛋仍是后续范围，详见 [研究方案](../../../starry-astronomy/proposal.md)。

## 验证

统一双主题预览生成成功；75 项自动检查全部通过。覆盖首次登记与同刻排序、补发旧日期、删除号保留与恢复、非法及重复编号、超过四位、档位变更、同日换篇、原字形字节一致、全部真实文章和两次准备结果不变，以及普通新文章在双主题和新检出中的登记。与 HEAD 对比，已有布局除新增 `catalogNumber` 外内容完全一致，真实文章原稿无改动。

沙箱中的首轮 HTTP 测试因不允许监听回环地址出现 6 项环境失败；取得本地测试运行权限后，完整 75 项重跑通过。浏览器同样在取得本地运行权限后验证。

复测需先运行预览服务，再从仓库根目录执行：

```bash
npm test
node .scratch/starry-blog/evidence/article-display-id-20261011/browser-check.mjs
```

浏览器脚本沿用本机已安装 Playwright 的路径，换机器需适配依赖导入；`CHROMIUM_PATH` 可覆盖浏览器路径，`STARFIELD_TEST_URL` 可覆盖本地预览地址。
