# 界面统一与手机布局修正 · 2026-10-12

作者要求以主控开发 Agent 身份自行评估并优化整体 UI 与动效，目标是“让整体风格更浑然一体，同时有一种高级但简洁的美感”，并授权修改任何素材。本记录是设计审查与实施结论；截图为本地归档。

## 审查方法

先用无头浏览器抓取首页房间、星空、观测面板、阅读页、检索（收起／展开）及手机竖屏共 12 张实况截图，逐页比对；再用 `getBoundingClientRect` 量测手机导航与面板的真实矩形，避免依据样式表推断。关键结论均来自量测而非目测。

审查脚本：`capture.mjs`（截图）、量测脚本见下节命令。

## 发现的问题

1. **手机竖屏观测面板与星盘入口重叠**。量测：面板人物剪影矩形 `x 7–94, y 592–697`，星盘入口 `x 14–86, y 686–758`，纵向压叠 11px。人物与星盘直接相撞，是本次最明显的缺陷。
2. **导航栏三种控件各用一套语言**。`关联／时间` 用青色下划线、图标按钮用另一条下划线、`旧版` 没有任何下划线；且 `旧版` 使用 `system-ui` 字体，与全站字体栈不一致。
3. **阅读页底栏与蓝面割裂**。`progress-track.webp` 有 56% 的近黑像素，在蓝色纸面上像挖了一个洞；正文标题与各级标题使用 600 字重，与站点整体的 400 字重语言冲突。
4. **归档／标签／分类面板是浅色纸面**。设计文档把归档定义为场景物件（`归档星历盘`），但实现是暖白纸面板浮在蓝色插画上，视觉上像另一个站点叠在上面。
5. **星盘入口图稿对比度过高**。素材为 `1254×1254`，其中 41% 是近白线框，在厚涂星空上像一块 UI 面板。
6. **观测面板细线直接画在云上**。白色细线在小圆、刻度、年份处会被云块随机切断，缺少托底。

## 实施

新增 `source/css/starry/tokens.css`，作为唯一的设计令牌来源：深蓝色阶、面板填充与发丝线、墨色四级、青色／钴蓝双温度强调色、六级字号阶梯、三单位间距、圆角与发光。其余样式表改为引用令牌，不再各自硬编码颜色。加载顺序在 `layout.ejs` 中置于最前。

- **手机布局**（`search.css`、`observation.css`）：观测面板改为左右各留 8px 的满宽底栏；星盘入口引入 `--entry-lift`，在面板可见时上移 216px。修复了一处优先级错误——原 `bottom:86px` 覆盖了 `calc()` 基值，改为在基值与手机规则中都写 `calc(86px + var(--entry-lift))`。量测确认入口底边 542px 对面板顶边 579px，不再重叠。
- **导航统一**（`scene.css`）：三种控件共用同一发丝线基线，`关联／时间` 保留较亮的一档；修正 `#exploration-controls .icon-control` 的 `border:0` 覆盖新下划线的优先级问题。`旧版` 改用 `var(--sans)`。`blog-theme-switch.css` 同步字体与颜色，并保留旧版站点的独立配色。
- **观测面板**（`observation.css`）：加一层极淡的径向底色承托细线，不形成卡片感。
- **星盘入口**（`search.css`）：`brightness(.86) saturate(.72)` 降低线框对比，悬停／聚焦恢复原亮度。尺寸、轴心与指针旋转未改动。
- **阅读页**（`reader.css`）：底栏用 `background-blend-mode: screen` 把深蓝洗色并入轨道自身图层以抬升黑位（单独的 `screen` 图层无法抬升纯黑，这是本轮修正的一处实现错误）；标题字重统一为 400。
- **清单面板**（新增 `collection.css`）：把 `#collection-panel` 的框架移入夜色配色，正文与列表改用冷色墨；无 JavaScript 的静态回退保留浅色纸面，因为那里没有星空托底。

## 验证

89 项自动测试通过，双主题生产构建通过（111 文件，新版在 `/`、Kira 在 `/legacy/`）。

浏览器检查覆盖 1440×900、1280×800、1920×1080、390×844 与横屏，房间、星空、观测面板、阅读页、检索收起与展开、归档页均无脚本异常。手机重测量测确认重叠消除；`旧版` 落地页 `--night-900` 为空值，确认令牌未外泄到 Kira 主题。

本记录只涵盖本地预览与生产静态构建。远程发布、真实触屏设备与第三方音频播放仍需按各自证据单独判断；本轮未线上发布。
