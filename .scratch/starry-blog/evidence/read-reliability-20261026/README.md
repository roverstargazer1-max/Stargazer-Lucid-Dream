# READ 等待与错误恢复

日期：2026-10-26。作者在对线上站点排查后授权修复。这里记录本地实现与验证；本轮未推送或线上发布。共享工作区同时进行的音乐移除与其他改动继续保留，不归入本次 READ 修复。

## 复现与结论

`node --test .scratch/starry-blog/evidence/read-reliability-20261026/regression.mjs` 在修改前稳定失败两项：

- HTML 已就绪、装饰请求不结束时，READ 仍不能展开正文。
- 后台预取失败会恢复上一颗选星，撤回当前选择。

另两条直接原因：文章 `fetch` 缺少应用层超时；靠近／加载文案只有屏幕阅读器可读，且原图按钮的高优先级样式覆盖了禁用透明度。线上手机宽度复查中，到位后的 READ 屏幕触点可以打开文章，未复现到就绪状态的热区遮挡。

更正初次探测的素材体积：3,192,324 字节是保留原图，页面实际 `data-reader-*` 指向 `images/optimized/interface-reader-*.webp`，三张显示缓存合计 **455,688 字节**（324,442 + 77,872 + 53,374）。本轮没有重新压缩或替换素材。

## 改动

- 靠近、就绪和加载状态在 READ 下方直接可见；禁用时降低透明度，不再显示悬停提亮。
- 阅读正文不等待底图或字体；点击时提升已有装饰请求优先级，场景和开合时长沿用。
- `article-loader.js` 统一文章载入：相同文章共享正在进行的请求、复用已验证的正文节点；直达页面复用已有正文；保留文章身份与正文存在性校验。
- 单次请求在 8 秒内覆盖响应头与正文接收，超时取消；失败清除正在请求的记录，下一次 READ 可重试。使用正常 HTTP 缓存策略，取消每次强制重新验证的请求选项。
- 预取失败不修改选星；读取过程中被中断后，迟到结果只可进入正文缓存，不会自动展开旧文章。
- 失败时保持原地址与选星，READ 恢复可用，并显示有 44px 高度点击范围的“直接阅读”链接。
