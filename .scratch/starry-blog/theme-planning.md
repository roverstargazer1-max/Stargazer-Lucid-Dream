# 星空博客正式化：需求访谈

日期：2026-10-01。状态：四轮访谈已完成，关键需求与实施方向已确认；实施顺序和验收见 theme-production-plan.md。

## 本次明确要求

- 将已接近完成的原型整理为博客主题，参考当前 hexo-theme-kira。
- 完整保留文章、图片、旧主题及配置，需要时切回旧版。
- 先访谈技术和需求细节，再制定实际计划。
- 评估与现有 GitHub 推送后由第三方自动构建、托管静态博客的方式是否兼容。

## 已核实的环境事实

- 当前站点为 Hexo 8，正式主题仍是 hexo-theme-kira。
- 本地 themes/hexo-theme-kira 为 Git 跟踪的自定义主题；根依赖还包含同名 npm 包，不能将两者当作同一来源。
- 当前 dev 工作目录的星空原型位于 themes/hexo-theme-kira/prototypes/starfield，为 V13，仍使用 mock 文章。codex/prototype-starfield 分支有 V20 及独立正式主题；作者在第四轮明确选定 V20 为最终体验基准。
- source/_posts 有 10 篇真实 Markdown；文章 URL 规则为 :year/:month/:day/:title/。
- 现有内容含 cover、cover_mobile、sticky、reprinted、HTML subheading 等字段，以及 meting 音乐标签和相对图片路径。
- 现有独立页面包括 /pages/archive/、/pages/friends/、/pages/mine/；友链数据保存在 Kira 配置中。
- Gitalk 和 Giscus 当前均未启用。
- netlify.toml 配置构建命令 npm run netlify、发布目录 public；该脚本先执行 Hexo clean，再 generate。
- 仓库同时存在 npm 与 pnpm 锁文件，未固定托管构建使用的 Node 版本。
- 托管平台实际绑定分支、运行环境、在线部署结果和账号限制尚未核实；仓库配置提示平台很可能为 Netlify。

## 已确认的首轮决策

1. 首先用于作者自己的博客，稳定后再考虑开放；不以首版交付公开安装包或完整项目模板为目标。
2. 旧版完整保留，作者需要时可以切回；不要求两个版本同时在线。
3. 继续写 Markdown，在文章开头填写少量配置，再推送 GitHub 发布。
4. 首版只需实现当前最终原型已有的全部功能。上一轮列出的归档、搜索、友链、评论、跨次记忆等建议不构成新增需求。

## 已确认的第二轮决策

- 首版采用厚涂窗边版本与 C 阅读方式的访客体验；补查前暂用当前目录的 V13 描述，第四轮已明确以 V20 替代。不包括调试面板、试加模拟文章、导出布局、旧版美术和 A/B 方案切换。
- 沿用 Hexo、EJS 模板、原生 JavaScript 与 Canvas。
- 现有真实文章全部自动成为文章星。
- 通过文章开头的自定义字段指定关联文章，使用方式类似 tags、cover；目标引用与关系规则已在第三轮确认。
- 直接访问文章链接时先展示该篇正文，关闭阅读后进入星空。第四轮已确认保留原链接与内容，地址兼容按最终计划验收。

## 原型数据行为与正式化差距

- 内容关联是人工配置的 15 条关系，读取时双向匹配，同一理由在两个方向展示；探索路径独立于内容关联。
- 星等在 mock 中写死为普通、重要、珍藏；孤立只排除自动探索与时间连线，不排除人工内容关系。
- 半球初始布局每次按文章数组下标重新分配位置；插入、删除、排序会移动旧文章星。
- 原型时间布局依赖数组下标，未使用真实发布日期排序。
- 已读、选中、停靠历史及阅读前镜头状态仅保存在内存，刷新丢失。
- 正文当前只从 mock 段落生成 p 元素，真实 Markdown 的图片、标题、代码块和自定义标签仍需接入与验证。
- 已有真实正文使用标题、列表、引用、加粗、链接、相对路径图片和原生 HTML / style；正式阅读器必须保留这些内容，并防止文章样式影响场景。
- 厚涂背景使用原生 WebGL。目前获取上下文失败仅剩基础蓝底、碎星和月亮；着色器异常与上下文丢失未完整处理。
- 厚涂版当前还会请求未显示的两张旧屋顶素材，文件大小合计约 4.1 MB；正式版需清理这些无用途的加载。文件大小是静态核查，非网络性能测试结果。

## 已确认的第三轮决策

- 关联字段填写 Markdown 文件名，不含 .md；修改文件名时同步更新引用。
- 内容关联自动双向，理由选填；未填理由时文末仍显示关联文章入口。
- 保持旧星的位置，新文章自动寻找空位。
- 接受按设备性能自动减少背景星、画面分辨率与装饰动态；文章星、导航、阅读及返回等核心功能保持可用。
- 直接接入当前已有的全部真实文章；首版不使用模拟文章，不做面向额外文章规模的设计或验证。

## 已确认的第四轮决策

- 以最后体验并认可的 V20 为最终原型基准。
- 写完文章后先执行一次本地预览，由预览自动准备并保存新星位；提交文章和布局后推送 GitHub。
- 保留旧独立页面原链接和内容，进行最小兼容承接；首页保持最终原型界面。

## 补查分支的事实与优先级

- 当前 dev 未跟踪远端分支；在线 GitHub 默认分支为 master。实际 Netlify 生产分支尚未确定。
- codex/prototype-starfield 分支已有 V20 原型、themes/stargazer-starfield、prepare-starfield.cjs、稳定布局文件、真实文章阅读、双向关系和集合路由等实现。只读检查，没有切换或合并该分支，也未运行其构建或验收。
- 该分支的旧计划包含公开模板、场景校准工具及通过独立数据文件引用稳定 ID 的关系配置；这些旧要求不能覆盖本次新答复。
- 本次需求优先：个人站点先行，关联写在文章 Front-matter 并按文件名引用，只用现有真实内容验收。内部自动生成的身份可作为复用细节，不要求作者维护编号。
- V20 包含连续穿窗、反向归窗、正文书页开合、简介动画、窄屏布局与操作热区等晚于 V13 的优化。现已确定为体验基准。
- 该分支已有本地 prepare:starfield 步骤，可以接入已确认的预览准备流程，保存布局后随文章推送。

- 10 篇现有文章文件名互不重复，且均不在子目录；符合此次文件名引用约定。
- GitHub 查询未返回对应提交的状态检查，不能据此断言有无部署或部署成功。

已读与阅读前镜头恢复按最终原型的本次访问范围整理；跨次保存不是目前已确认的首版需求。

技术事实补充：厚涂背景的 dome-renderer.js 已使用原生 WebGL；整理正式版时需要保留该现有实现，Canvas 与 WebGL 均属于当前原型的渲染组成。
