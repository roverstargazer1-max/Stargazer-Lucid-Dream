## Problem Statement

作者已有接近完成的 V20 星空博客原型，希望把它用于自己的真实博客，并进一步提供别人可以复制、修改配置后建站的完整模板。当前原型使用虚构文章，处于旧主题的实验目录中，没有正式内容管线、持久星位、完整地址兼容或经过验证的生产发布流程。直接发布原型无法满足真实写作、内容阅读和可配置使用的要求。

作者的博客通过推送 GitHub 仓库触发 Netlify 静态构建发布。改版需要保留这条流程，保留旧版主题、配置、原始内容和素材，能够恢复旧版；公开模板将另开仓库，不能混淆作者个人博客与给别人使用的模板。

预期使用者会写 Markdown、改配置并按教程运行安装命令。用户希望支持内容、外观、桌面及手机插画和互动区域自定义，日常使用不需要修改前端代码。星空体验失败时，真实文章仍须在同一地址可读。

## Solution

保留现有 Markdown 和 Hexo 写作、渲染与静态构建流程，建立与旧 Kira 版本独立的正式星空主题。采用 EJS 页面模板、原生 JavaScript 模块、CSS 和现有 Canvas/WebGL 效果，接入真实内容，保留 V20 的窗边穿窗、穹顶探索、选星推进、阅读与返回体验。

每篇文章预生成真实正文及标题、摘要和分享信息，正常运行时呈现星空阅读层，脚本或渲染失败时仍可阅读。文章具有固定身份，关联模式的星位保存到仓库；本地发布准备步骤自动补身份和新增位置，Netlify 使用提交的数据生成站点。作者维护一条双向关系即可在两篇文章两边生效，语义关系与邻近导航路线明确区分。

配置覆盖个人内容、视觉参数和桌面/手机场景；本地可视化校准工具让使用者点选或描画互动区域、遮罩并导出配置。低性能设备可以减少装饰效果，核心探索、穿窗和阅读保留。归档、友链及旧标签/分类链接在星空内承接对应内容，正常首页不增加常驻文字菜单。

首版暂缓新作者介绍及首页介绍入口，未来书桌物件跳转只记录为后续设想。旧关于地址保留现有内容的轻量兼容呈现，原文件和歌单保留。先在作者的个人博客验证、上线并验证恢复旧版，再另建公开模板仓库，提供通用示例文章、通用插画、配置示例和安装部署说明。

## User Stories

1. 作为作者，我希望继续在本地 Markdown 文件中写文章，以便沿用已有的写作习惯。
2. 作为作者，我希望继续推送 GitHub 触发 Netlify 发布，以便保持现有的静态托管流程。
3. 作为作者，我希望先在个人博客验证真实内容和上线流程，以便在公开模板前发现实际问题。
4. 作为作者，我希望保留旧版博客的主题、配置、内容和素材，以便随时恢复使用。
5. 作为作者，我希望有经过验证的旧版恢复步骤，以便新版出现问题时能够重新发布旧版。
6. 作为作者，我希望现有全部文章都成为可探索的文章星，以便真实作品进入星空体验。
7. 作为作者，我希望原有文章地址保持有效，以便过去分享的链接仍对应原来的文章。
8. 作为作者，我希望文章标题、文件名和日期修改不会混淆文章身份，以便跨布局仍识别同一篇内容。
9. 作为作者，我希望发布准备步骤自动补文章身份和新星位，以便不用手工维护空间坐标。
10. 作为作者，我希望重复准备发布不会改变已有星位或重复创建身份，以便提交结果可预测。
11. 作为作者，我希望新增没有关系的文章也能正常发表，以便关系维护不成为写作门槛。
12. 作为作者，我希望新增文章不移动关联模式的旧星，以便保留已经熟悉的空间位置。
13. 作为作者，我希望后补关系不会重新排列旧文章星，以便内容关系可以逐渐完善。
14. 作为作者，我希望文章更名、补发、删除后恢复仍有清楚的身份和地址处理，以便维护内容不破坏既有入口。
15. 作为作者，我希望时间模式按发表日期稳定组织文章，以便读者能观察写作时间的延伸。
16. 作为作者，我希望手填文章引言，并在未填写时自动提取纯文本，以便兼顾表达与省事。
17. 作为作者，我希望一条关系配置在两篇文章两边生效，以便不重复维护双向关系。
18. 作为作者，我希望只公开自己采用的关联与理由，以便未确认的 AI 候选不代表我的判断。
19. 作为作者，我希望星座名称可选且不要求围绕名称写作，以便星空服务表达而不限制创作。
20. 作为作者，我希望失效的可选关系有可定位提示且有效文章仍可访问，以便局部配置错误不让内容消失。
21. 作为访客，我希望从当前暖灯窗边进入同一片实时星空，以便入口、穿窗与探索连成统一体验。
22. 作为访客，我希望拖动观察上半球天空，以便发现首屏以外和天顶附近的文章。
23. 作为桌面访客，我希望通过拖动和滚轮探索，以便自然调整朝向与距离。
24. 作为手机访客，我希望通过单指拖动和双指张合探索，以便在触屏上完成同样的流程。
25. 作为访客，我希望第一次点星只选中、靠近并显示引言，以便先了解文章再决定阅读。
26. 作为访客，我希望推进中重复点击不会排队打开正文，以便快速操作不会误进入阅读。
27. 作为访客，我希望到位后再次点同一颗星能读正文，以便不用执行快速双击。
28. 作为访客，我希望推进途中能改变目标或手动中断，以便保持对探索的控制。
29. 作为访客，我希望中断后再次点星先完成靠近，以便不会误触正文打开动作。
30. 作为访客，我希望点空白能取消选中但拖动不被当作空白点击，以便镜头操作和选中状态清楚。
31. 作为访客，我希望在阅读前就能探索关联文章，以便关联导航不需要解锁正文。
32. 作为访客，我希望长文到末尾和短文完整可见都能显露作者采用的理由，以便无需等待计时或读完两端文章。
33. 作为访客，我希望无理由时没有虚构解释，以便看到的关联信息来自作者。
34. 作为访客，我希望关闭阅读后回到进入前的镜头和选中星，以便继续原来的探索。
35. 作为访客，我希望返回上个停靠点和返回窗边有明确入口，以便不会迷失在天空深处。
36. 作为访客，我希望切换关联与时间模式时继续聚焦同一篇文章，以便比较布局不丢失阅读目标。
37. 作为访客，我希望时间相邻不被解释成语义关联，以便时间排序不会产生虚构关系。
38. 作为访客，我希望阅读层的滚动和触摸不会移动背后的镜头，以便专心阅读。
39. 作为访客，我希望直接打开或刷新文章链接就能阅读对应正文，以便不必先从入口寻找文章。
40. 作为访客，我希望浏览器前进后退与显示文章一致，以便地址和当前内容始终对应。
41. 作为访客，我希望脚本禁用、启动失败或渲染不可用时同址正文仍能读，以便星空失败不阻止内容访问。
42. 作为访客，我希望原文的图片、HTML、页内锚点和音乐仍能使用，以便改版不损失原内容。
43. 作为访客，我希望音乐由主动操作播放，以便阅读不会受到自动播放干扰。
44. 作为访客，我希望手机阅读层使用可用空间、横竖屏切换后仍可操作，以便完整阅读长文。
45. 作为访客，我希望紧凑屏幕的简介和方位图不遮住核心操作，以便仍能找到目标星与阅读入口。
46. 作为访客，我希望减少动态设置获得轻过渡，以便按自己的动效偏好浏览。
47. 作为低性能设备访客，我希望减少装饰星、云细节和微动后仍能探索、穿窗与阅读，以便设备能力不妨碍核心流程。
48. 作为访客，我希望通过星历盘选择有文章的年月，以便进入对应时期的内容。
49. 作为访客，我希望旧标签、分类与分页地址对应正确的文章集合清单，以便旧链接的范围不变。
50. 作为访客，我希望友链信号显示朋友信息并由我主动打开外链，以便探索时不会被自动带走。
51. 作为旧关于链接的访客，我希望仍能看到该地址已有的内容，以便新介绍暂缓时链接仍有意义。
52. 作为作者，我希望正常首页没有新增常驻文字菜单，以便保留当前场景探索方式。
53. 作为作者，我希望首版保留原型已有的小交互，以便维持趣味而不追加新彩蛋工作。
54. 作为模板使用者，我希望复制完整项目即可开始配置，以便不需要先组装主题和站点骨架。
55. 作为模板使用者，我希望通用示例文章和房间插画能直接预览，以便理解模板效果并替换成自己的内容。
56. 作为模板使用者，我希望修改内容、友链、文案和视觉参数即可定制，以便日常使用不必编辑前端代码。
57. 作为模板使用者，我希望分别替换桌面与手机入口插画，以便每种画幅有合适构图。
58. 作为模板使用者，我希望在本地界面点选或描画窗口、遮罩和互动区域，以便不同插画可以配置穿窗效果。
59. 作为模板使用者，我希望校准工具能预览入口、穿窗和返回并导出配置，以便发布前验证场景。

64. 作为作者，我希望公开模板独立于个人博客仓库，以便模板不携带个人文章、个人素材或旧 Kira 版本。

68. 作为维护者，我希望按先真实文章、再全量内容、后公开模板的顺序实施，以便每个阶段都有可评估的完整结果。

## Implementation Decisions

以下决定承接用户已确认的方案，按职责描述模块和接口，不绑定具体源文件名或目录。

1. **技术基线与版本选择。** 保留 Hexo、Markdown、现有 EJS 渲染能力和 npm 发布流程；正式星空使用原生 JavaScript 模块、CSS、Canvas 2D 和当前 WebGL 投影。以实际干净构建固定依赖与 Node 运行时。已知两套锁文件的 Hexo 版本不同，统一使用基线须同时验证旧版构建，不能以主题迁移为由顺带升级或删除旧版所需依赖。
2. **主题与内容边界。** 旧版主题及原型证据保留，建立独立正式星空主题。个人内容和场景、主题通用实现、作者工具分别组织；公开模板后续从通用实现和配置能力整理，日常自定义不要求修改通用代码。
3. **静态内容适配模块。** 输入现有 Hexo 文章、页面、已采用关系及配置，输出稳定文章身份、标题、日期、纯文本引言、原地址、正文入口和布局引用。正式阅读使用 Hexo 渲染结果，不延续原型的虚构段落数组。文章封面、置顶及已有标签等元数据保留；其呈现适配不扩大为新栏目或传统首页。
4. **正文 HTML 与页面信息。** 每个真实文章地址生成可读正文、真实页面标题、摘要、规范地址和分享信息。静态内容先可读，只有星空和相应内容准备成功后才切入增强体验。脚本禁用、加载失败、运行失败和 WebGL 不可用均不能留下无法阅读的空页面。
5. **按文章加载与链接契约。** 入口使用轻量文章索引，正文按实际阅读目标加载；所有内容链接保留真实可导航地址。加载另一篇文章失败时保留已可读内容并提供真实地址访问，不把失败标记成成功切换。历史导航、直接打开、刷新、正文锚点和集合页均指向对应内容，静态托管不以统一首页回退掩盖缺失路由。
6. **文章身份与地址契约。** 固定身份独立于显示标题、文件名、数组顺序和缓存 ID。首次导入记录实际原地址并保持旧链接；显示标题修改不改变身份，文件更名或日期更改仍保持已保存的地址与身份。删除内容的记录与恢复处理须保持其他文章身份和位置，草稿状态不得仅凭正文措辞推断。
7. **稳定关联布局模块。** 输入固定身份、已有位置和作者采用的关系，为新文章分配位置并保存版本化结果。已有坐标不因新文章、后补关系或重新构建而全局重排。新增无关系文章也有位置；初始空站点、孤立文章和位置拥挤应有可发表的结果。视觉留白以当前原型为基线，普通视野约 3–6 颗是校准目标，不是强行隐藏内容的计数规则。
8. **时间布局。** 根据发表日期和固定身份确定稳定顺序，同日期排序可重复。补发旧日期文章会调整时间序列落点，但不会修改关联模式保存的位置；两种模式识别同一篇文章。
9. **关系契约。** 作者配置的一条语义关系默认双向，引用固定文章身份，理由可选。只公开作者采用的结果，候选不自动发表。邻近导航路线只帮助探索，不冒充语义关系，不产生关联理由，也不因星座显示名称而限制写作或重排位置。
10. **本地发布准备模块。** 作者写文后运行本地准备步骤，自动补固定身份、分配新星位并校验输入，生成数据与文章一起提交。相同输入重复准备的结果稳定；尽量接入现有本地构建体验。Netlify 校验并消费提交的数据，缺少新文必要身份/布局时给出具体准备提示，不把 CI 临时分配的位置当作已保存状态。
11. **配置边界。** 使用可编辑 YAML 表达内容、关系及主题选项；工具生成的布局与场景数据使用带版本字段的 JSON。配置覆盖内容与文案、友链、字体配色、星光云层与动画参数、桌面手机素材及互动区域。新增可选项具有兼容默认值；缺少可选关系、星座名或引言不会阻止有效文章展示，失效关系跳过并给作者可定位提示。重复身份、重复内容地址和无法使用的必需数据明确报错。
12. **本地场景校准模块。** 使用本地 Node 工具提供图片校准界面，桌面和手机分别标记窗口通透区、点击区域、遮罩与镜头参考。配置坐标相对于图片，能够复现裁剪和缩放后的入口、穿窗与返回；支持导入、预览、导出和取消。导出由作者明确保存和提交，工具不自动覆盖原素材或正式配置。首版只做校准能力，后续书桌物件的作者介绍跳转暂缓。
13. **探索与阅读状态模块。** 沿用当前窗边、穹顶、穿窗与阅读的视觉语言。首次点星选中并靠近，到位后再次点同星才阅读；推进中的重复点击不排队，改变目标和手动操作可以中断。中断后下一次点星重新完成靠近；空白点击取消选中但不改变镜头，拖动结束不算空白点击。内容层展开时隔离背后镜头手势。
14. **模式、停靠与返回。** 有选中文章时切换模式聚焦同文；未选中时进入目标模式默认起点。当次访问共享阅读标记，刷新不恢复探索历史。自动停靠完成后记录返回点，手动巡视不逐帧记录；切换模式后建立当前布局的停靠起点。关闭正常阅读恢复进入前状态；直接链接打开的文章关闭后回对应关联星附近，并可回窗边。浏览器历史与当前内容层及地址同步。
15. **阅读标记与关系显露。** 长文到正文末尾、短文完成布局即完整可见时满足显露条件，无停留计时。读完当前文章即可查看作者采用的理由，不要求两端都读；没有理由不填占位文案。时间相邻不生成语义关系，时间模式默认不展开语义线；已满足阅读条件的文章仍能查看其采用理由。简介完整呈现的当次缓存与正文读完标记分别维护。
16. **功能入口与兼容集合。** 首版保留归档星历盘和友链信号，旧标签、分类及分页地址进入星空内相应内容范围的清单。归档只提供有文章的年月，定位对应时期起始文章。正常首页没有新增常驻文字菜单；功能入口通过轻反馈可发现，桌面悬停/靠近后点击，手机首次触碰提示、再次点按展开。友链由主动操作在新标签页打开，保持当前星空。
17. **作者介绍与旧关于。** 首版不新建作者介绍或首页介绍入口，不整理新的介绍稿，也不把旧歌单迁成新手记功能。原关于内容、歌单与地址保留，旧地址以轻量兼容呈现承接已有内容；不会回到旧主题整套布局。未来点击书桌物件前往作者介绍是候选扩展，不属于本次首版。
18. **媒体与旧插件兼容。** 真实正文的 HTML、内联样式、图片、相对路径、锚点和音乐属于兼容范围。播放器依赖按实际内容加载，音乐由主动操作播放，不新增全站自动播放。旧 Kira 的全局正文过滤与重复标签注册可能影响新主题，须验证并限定适用范围或隔离构建；保留旧版所需资源和依赖。旧归档或关于页的独有音乐不自动迁成新全站功能，旧关于承接遵循上一条。
19. **设备与动效。** 桌面、手机横竖屏沿用 V20 的阅读构图、可用热区、紧凑简介和按需方位图。保留键盘可操作与焦点返回、文字放大时可读。系统减少动态偏好与设备性能降级分别处理；低性能模式减少装饰星、云细节、微动和必要的渲染分辨率，保留核心探索、穿窗和阅读。WebGL 完全不可用时仍有静态可读路径。
20. **视觉与小交互基线。** 使用当前选定的 C 阅读方向、厚涂云景、窗边构图和 V20 往返动效作为正式化基线；桌面以回退后当前素材为准，手机沿用已有独立竖版。首次过渡与重复简介的节奏分别保留，通过真实画面和设备校准。沿用已有小交互，不追加原稿中尚未制作的新彩蛋、隐藏地图或任务系统；调试对照不进入正式界面。
21. **Netlify 与恢复。** 延续 GitHub 推送触发静态构建，正式发布目录保持既有约定。核对实际生产分支、安装工具、Node 版本、构建上下文与资源缓存，先独立预览再正式切换。保存可识别的旧源代码、配置、依赖与部署记录，并验证切回旧配置后干净构建及发布的恢复流程；不能仅凭主题目录存在就认为恢复能力已成立。
22. **公开模板边界。** 作者站点完成验证上线后，另建完整模板仓库，包含通用实现、示例文章、通用房间插画和配置/部署说明。模板不携带作者个人文章、个人场景、旧 Kira 版本或原型 mock/调试输出。默认素材来源与再分发条件清楚；验证空环境复制、改配置、校准、写文、准备、构建与 Netlify 部署完整流程。

## Testing Decisions

### 测试边界与质量原则

- 主测试边界是**准备并生成的静态站点，以及访客通过真实地址使用它的浏览器行为**，覆盖内容输入到最终呈现。此边界沿用用户已确认的技术方案、阶段 1 的真实文章链路和既有验收要求，不再次要求用户确认相同范围。
- 测试通过公开的作者操作、生成结果、链接导航、画面状态和校准导出结果判断行为，不依赖私有函数、内部数组顺序、具体模块文件名或对实现公式的照抄。优先在同一条完整链路验证数据、路由、内容和交互，减少需要同时维护的内部测试接口。
- 本地发布准备与场景校准的公开输入/导出结果是补充测试边界：验证幂等性、身份/布局稳定、导入导出与实际预览一致。只有浏览器难以稳定触发的取消、改选和位置分配边界才补充少量纯逻辑测试。
- 自动断言覆盖确定的外部行为。画风、留白、动画节奏、可发现性和真实触屏手感采用与当前原型对照的实际体验；不给每个视觉数值写镜像测试。
- 首个新增测试采用一篇真实文章，完成本地生成、同址正文、星空阅读、返回和失败回退，再扩展到全部内容；不能用 mock 全流程通过替代真实文章接入。

### 行为验收矩阵

| 场景 | 必须观察到的外部结果 |
| --- | --- |
| 新旧主题的干净构建 | 选定锁文件与运行时后两种布局均能生成；新主题没有破坏旧版依赖、资源或原地址。 |
| 全部现有内容 | 当前 10 篇文章及既有页面逐项核对；实际开始实施时更新内容清单，新增文章同样纳入。标题、正文、图片及页面范围不丢失，公开状态不因文字措辞改变。 |
| 同址静态阅读 | 禁用 JavaScript 直接访问文章，仍有正确标题、摘要和正文；规范地址与分享信息对应同文。 |
| 启动与资源失败 | 分别阻断主脚本、文章加载或 WebGL 初始化；保留或恢复可读内容及真实地址访问，不能留下空层或地址指向未加载文章。 |
| 原内容格式 | 相对/根路径图片、HTML、内联样式、代码块、正文锚点及实际使用的播放器逐项验证。音乐服务失败不阻止正文阅读。 |
| 地址兼容 | 文章、归档年月、标签、分类、分页、友链和旧关于地址直达/刷新正确；中文编码、站点根路径和锚点可定位。 |
| 选星与推进 | 首次点星只靠近；移动中连点不打开或排队；到位再点进入；换目标/手动中断后不会误开正文。 |
| 阅读与理由 | 长文到末尾、短文布局后完整可见均触发理由，无计时门槛；无理由不生成文字，未读也可以沿关系探索。 |
| 返回与模式 | 关闭正文恢复前置视角和选中项；返回点由完成停靠记录；切模式聚焦同文；直接链接无历史也能回对应星及窗边。 |
| 浏览器历史 | 文章切换、内容关闭、前进后退和刷新后画面对应地址；当次标记跨模式共享，刷新不恢复历史探索。 |
| 身份与布局 | 重复准备、干净重建、增加孤立文章、补远距离关联均不改变关联模式旧星位；更名、改日期、同日/补发、删除后恢复不串文。 |
| 双向与候选关系 | 一条采用关系两边生效；候选不公开；邻近导航线和日期相邻不生成语义关系。失效可选关系有定位提示，有效文章可访问。 |
| 缺省与错误配置 | 缺引言生成纯文本、缺星座名省略、归档不出现无文章年月；重复身份/地址或损坏必需数据产生明确错误。新可选字段缺省兼容。 |
| 场景校准 | 用一套不同构图的桌面/手机图片描画区域，导出、导入并生成预览；窗口、点击区域及往返过渡对齐；取消不覆盖原文件。 |
| 归档、集合与外链 | 日期入口定位正确时期，旧集合清单符合原范围，首页无新增常驻菜单；友链仅在主动操作后打开新标签页；旧关于呈现原内容，没有新介绍入口。 |
| 内容层与输入 | 正文、集合及旧页内容层滚动不移动镜头；拖动结束不取消选中；键盘、焦点返回和必需按钮均可操作。 |
| 视口与可读性 | 桌面、手机横竖屏、紧凑高度、文字放大与浏览器原生缩放分别验证，核心控件和正文仍可达；避免用 CSS 文字模拟代替原生缩放。 |
| 真机与降级 | 实际单指/双指、系统安全区与字体、横竖屏变化、减少动态及低性能模式完成核心流程；装饰下降不改变内容身份和导航。 |
| Netlify 与恢复 | 干净托管构建、资源路径、生产配置和独立预览验证；正式切换后按保存的旧配置恢复旧版；记录实际部署与恢复结果。 |
| 公开模板 | 空环境复制、安装、改配置/文章、校准、准备、构建和部署成功；模板只包含通用示例与允许再分发的默认素材。 |

### 已有测试与证据的使用

现有原型有针对简介完整呈现、取消/改选的当次记忆测试，以及覆盖多视口和天顶位置的停靠测试。它们可作为外部状态边界和几何结果测试的先例，必要时随正式接口整理；不得因为原型中通过就免除正式浏览器链路检查。

原型另有浏览器截图、操作矩阵、媒体与文字放大证据。V20 已记录真实触屏、跨系统字体及前台性能采样限制；测试计划必须继承这些限制，以实际设备和托管环境补齐。记录设备、浏览器、视口、动作、实际结果和证据；未实测项标记未验证，不把模拟视口宣称为真机通过，也不宣称固定帧率已经达标。

## Out of Scope

- 首版新增站内搜索、RSS、正文目录、代码高亮能力、数学公式或评论系统；已有内容格式的兼容不因此取消。
- 新作者介绍、首版首页介绍入口、整理作者经历或把旧歌单制作成新的手记功能；书桌物件跳转作者介绍留作后续设想。旧关于链接与原内容保留属于范围内。
- 全站自动播放背景音乐，音乐场景物件和未使用的所有旧主题自定义标签兼容。
- 跨次访问恢复探索、账号、云端数据库、跨设备同步、在线内容管理或关联管理后台。
- 访客端实时 AI、自动采用或发布关系候选、必须接入特定 AI 服务。
- 跨静态站点生成器适配、任意核心导航重写、读者自建星座、复杂游戏、隐藏地图或任务系统。
- 新增原稿提出但原型尚未制作的小彩蛋；首版沿用现有小交互。
- 新旧主题由访客实时切换、另建同时在线的旧站入口；已确认需求是作者能够恢复旧版发布。
- 公开模板携带个人文章、个人场景、旧 Kira 版本和原型实验界面。
- 本次规格编写直接实施代码、运行正式构建、部署个人站点或创建远程模板仓库。规格中的这些交付属于后续实现阶段。

### 已知事实和实施时核对项

当前正式站为 Hexo 加本地定制 Kira，星空仍是 V20 mock 原型。已知 npm 锁定 Hexo 8.1.2、pnpm 锁定 8.0.0；本地 Node 22.19.0/npm 10.9.3，仓库未固定运行时。主题目录隔离不等于插件隔离，旧目录插件可能影响正文锚点，旧播放器还依赖实际资源加载。上述事实用于实施准备，不证明新旧正式构建已通过。

实际 Netlify 生产分支、运行时、base directory、部署上下文、缓存及可恢复的历史部署仍需读实际配置核对。这属于阶段 0/5 的事实调查；不把未核对项列成新的产品需求，也不再询问已确认的 Netlify 平台或旧版恢复意图。
