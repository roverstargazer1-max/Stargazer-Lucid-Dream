# 星空博客主题化：需求访谈记录

日期：2026-09-30。
状态：访谈及整体复核完成；实施规格已发布为 `ready-for-agent`，正式实现和部署尚未执行。

## 本次用户明确的目标

- 以现有原型为参考，把效果包装成可供别人使用的博客主题。
- 使用者可通过自定义项和配置获得类似效果，并支持个性化。
- 原来的博客存档不删除，随时可以再用；第一轮已明确为作者可切回旧版并重新发布。
- 评估现有 GitHub 推送后由第三方自动构建和托管的静态发布流程是否兼容。
- 先通过 ask-matt 引导访谈，明确需求与技术取舍，再形成实际项目计划。

## 已核实的仓库事实

- 正式站点是 Hexo，本地主题为 `themes/hexo-theme-kira/`；站点配置仍选择该主题。
- `package.json` 的 `build` 为 `hexo generate`；`netlify` 为先 clean 再 build。
- `netlify.toml` 声明构建命令 `npm run netlify`、发布目录 `public`。
- Git origin 指向 GitHub 的 `roverstargazer1-max/Stargazer-Lucid-Dream`。
- 当前未见用于正式发布的 GitHub Actions workflow。仓库配置不能单独证明线上实际托管平台、监听分支和生效设置。
- `source/_posts/` 有 10 篇现有文章；原始文章、图片、页面和旧主题均保留。
- 文章永久链接配置为 `:year/:month/:day/:title/`；还有归档、标签和独立页面入口。
- 内容包含 Markdown、HTML、相对图片链接和音乐标签；关于页使用 `meting` 歌单标签，兼容不能只检查纯文本。
- V20 原型位于 `themes/hexo-theme-kira/prototypes/starfield/`。`app.js` 导入 `mock.js`，尚未接入真实文章与正式路由。
- 原型主体使用原生 JavaScript、Canvas 2D，天空投影包含自写 WebGL 渲染；不能仅因视觉表现认定必须换 UI 框架。
- 当前工作区包含既有未提交原型改动和素材；本轮不覆盖、不清理这些内容。

## 第二轮问题（已答复）

7. 技术迁移取舍：保留 Hexo 内容生成与现有写作方式，还是接受生成器、插件和构建流程迁移。
8. 星空之外的内容可达性：是否要求预生成可阅读正文，在脚本失败时仍可读，并具备搜索与分享所需内容信息。
9. 自定义插画方式：固定构图换图、配置互动区域，或提供本地可视化区域校准工具。当前代码存在图片配套 SVG 遮罩和硬编码互动区域，任意替图尚不能自动适配。

11. 设备能力下降时的体验：减弱云层和动效继续探索，或允许以阅读为主的备用呈现。
12. 公开模板的默认内容和美术：沿用个人场景，或准备通用示例文章与可再分发素材。

## 本轮数据实现事实

- 原型 `dome.js` 的 `arrangeDome()` 按数组序号选择初始方位，`domePosition()` 的时间模式也使用传入序号；不能把这些直接当作正式内容布局方案。
- 原型 `growDomeArticle()` 会保留已有坐标，但新增试验数据只在内存中；当前没有可提交的真实文章星位分配文件。
- `navigation.js` 明确区分探索路径和内容关系；自动生成的邻近导航线不代表作者采用的语义关联。
- 正式文章示例没有固定星图身份字段；文件名和日期参与现有地址生成。Hexo 文档明确 `:title` 指文章文件名，而非显示标题，内置 `:id` 也不保证缓存重置后的持久性。正式数据层需区分显示标题、文件名、固定身份与原地址。
- 正文原型以 `paragraphs` 数组渲染；正式版必须接入已有 Hexo 正文结果，兼容原内容格式，并满足 Q8 的静态可读要求。
