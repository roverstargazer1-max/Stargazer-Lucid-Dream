每票的工作循环：完整读取工单和必要上下文，实施一个可演示的完整行为，运行与风险相称的真实验证，修复失败，检查差异，在工单 Comments 记录环境、操作、结果与证据，只有验收满足才勾选并设 State: closed，随后提交本票，再继续下一票。遵循仓库与适用技能；已获用户授权的常规动作不要因为技能的一般建议再反复确认。不要为了测试数量重复验证，也不要跳过必要的浏览器或部署验收。

提交规则：每完成一票，创建一个独立、可回溯的本票 commit；消息包含 starry-blog 工单编号和实际行为，例如 feat(starry-blog-03): ...，类型按工作内容选择。不要把多票合成一个提交，也不要提前提交未来票的实现。提交前检查暂存差异，明确暂存与本票相关文件，避免无审查地 git add -A。工单关闭与验收记录纳入本票提交；提交编号映射以 git log 为准，进度日志记录结果即可，不为填自身提交哈希制造额外空提交。
