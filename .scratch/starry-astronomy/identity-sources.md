# 文章星身份与坐标：天文来源及设计推导

研究日期：2026-10-11。状态：研究提案、待作者讨论；不是已确认规格，不覆盖现有设计或实现。仅新增研究笔记，没有改应用代码。

## 核实的天文事实

| 事实 | 一手来源 | 对博客的启发（以下启发属于设计推导） |
| --- | --- | --- |
| IAU 区分日常使用的星名（如 Vega）与星表里的字母数字 designation（如 HD 172167）。 | [IAU：Naming Stars](https://iauarchive.eso.org/public/themes/naming_stars/) | 文章标题、短星表号、坐标不必塞进同一个字段。标题允许改变，星表号负责持续识别。 |
| SIMBAD 标识通常由星表缩写与编号、字母或坐标组成；同一个对象可以通过不同名称检索，也支持以它为中心查询周围对象。 | [CDS/SIMBAD：Query from identifiers](https://simbad.cds.unistra.fr/Pages/guide/sim-fid.htx) | 以“私人星表 + 稳定编号”为主标识，文章标题、旧 ID、旧地址、可选星名作别名；以坐标作空间检索入口。 |
| IAU 的命名指南要求位置型 designation 截断坐标而非四舍五入；保留前导零与纬度正负号；J 与 B 有明确的参考系统含义；测得更好位置后不应每次改变 designation，近邻可以加补充标记消歧。 | [IAU Style Manual §7（历史正式命名规范）](https://iauarchive.eso.org/static/publications/stylemanual1989.pdf) | 坐标型名称是冻结的名字，不是永远更新的地址。不可因文章移动或场景切换自动改 ID；低精度坐标也不自然保证唯一。 |
| 2MASS 的形式为 `2MASS Jhhmmssss±ddmmsss`（小数点不写入名字）；其名称里的坐标有截断误差，精确位置应读独立的 RA/Dec 列。页面示例包括 Vega 的 `2MASS J18365633+3847012`。 | [IPAC/2MASS：Source Naming Convention](https://irsa.ipac.caltech.edu/data/2MASS/docs/releases/allsky/doc/sec1_8a.html) | 将“读起来像天文标识”与“实际用于定位的数值”分离，这是天文星表本身已有的做法。 |
| SDSS 正式 designation 使用 `SDSS JHHMMSS.ss+DDMMSS.s`。其文档列举缩短名称、遗漏 J 或错误舍入导致多个匹配对象与错误查询的案例。 | [SDSS：IAU designations](https://classic.sdss.org/dr2/coverage/IAU.php) | 不应把一长串坐标当成必须手填的唯一查找键；缩写可用于展示，但需要可靠星表号兜底。 |
| 赤经/赤纬构成天球位置；赤经常用时、分、秒，赤纬用角度。赤经的“时”是角度刻度，不是发布时间钟点。 | [NASA：Reference Systems](https://science.nasa.gov/learn/basics-of-space-flight/chapter2-2/), [NASA HEASARC：Coordinates Help](https://heasarc.gsfc.nasa.gov/Tools/name_or_coordinates_help.html) | 24h 可作为球面的整周刻度，但若把文章钟点硬当赤经，属于博客人为映射，不能称为实际天文学计算。 |
| 地平方位角/高度角依赖观测者经纬度及观测时刻；由赤经赤纬转为它们需要恒星时与观测地点。 | [USNO：Computing Altitude and Azimuth](https://aa.usno.navy.mil/faq/alt_az) | 场景内 az/el 与现实星表 RA/Dec 不能直接互换。没有地点、时刻、变换定义的穹顶坐标应标成本站星位。 |
| ICRS 是空间固定、相对远方源不旋转的参考系统；J2000 equinox 属于较早的动力学参考系统语境。二者普通应用近似一致，精密用途需做参考系变换。坐标 epoch 又是恒星自行所用的参考时刻，不能与 frame/equinox 混为一谈。 | [ESA/Gaia FAQ：ICRS / ICRF / J2000](https://www.cosmos.esa.int/web/gaia/faqs) | 虚构博客坐标不必挂上 J2000。选用真实参照星时保存来源星表、数据版本、参考系、坐标历元，避免只写“J2000”来涵盖一切。 |
| Gaia 的数字 source_id 在指定 data release 内唯一，但跨版本不能保证同号同源；完整 designation 包含 `Gaia DRx`。source_id 本身还编码近似位置与序号等信息。 | [ESA/Gaia DR2：gaia_source datamodel](https://gea.esac.esa.int/archive/documentation/GDR2/Gaia_archive/chap_datamodel/sec_dm_main_tables/ssec_dm_gaia_source.html) | “带空间信息的 ID”仍需命名空间与版本约束。博客没有必要照抄复杂的 64 位编码，保留简明私有星表号更利于填写。 |
| JD 是连续日及日的小数表示。经典整数日界在 UT 正午；精确用途必须声明时间尺度。MJD = JD − 2400000.5。USNO 转换器用 UT1，零时对应 JD 小数 .5。 | [USNO：Julian Date Converter](https://aa.usno.navy.mil/data/JulianDate), [USNO：Glossary](https://aa.usno.navy.mil/faq/asa_glossary) | JD/MJD 很适合作为发布日期旁的小彩蛋，但只是时间标度，不能凭自己保证文章唯一；不应把只知道日期的旧文章伪装为有精确观测时刻。 |
| TNS 使用年份与字母的 astronomical transient 名称，之后以谱学确认的超新星加 SN 前缀。 | [TNS：Getting started](https://www.wis-tns.org/content/tns-getting-started) | “年份 + 登记序列”也有真实天文先例。博客可以借鉴登记感，但文章持续存在，未必适合以瞬变事件为核心比喻。 |

## 建议：私人星表号、本站星位、现实参照星分别负责一件事

推荐主身份采用私有星表号，例如 `SLD 0042`（SLD = Stargazer’s LucidDream，示例前缀未获任何正式星表注册）。它是本站文章编号，不声称文章就是被发现的恒星、不声称获得 IAU 认证。已有内部身份与旧链接应继续映射到同一篇文章；短编号只提供更易记的公开入口。

主研究代理查到仓库旧讨论已有 `SG-0001`，它仍是提案。这里的 SLD 仅为说明结构，不建议同时推出多个前缀。最终可以沿用 `SG-0001`，或选更短的 `LD-0001`；本文不替作者确定。

1. 首次登记后编号冻结。改标题、改发布日期、移动星位、增加文章、改排序都不改号；已发出的号码不复用；历史文章以后补入也不对全站重新编号。草稿是否立即预留编号可由写作流程决定，一旦公开引用则冻结。
2. 稳定编号与本站基准星位分别保存。基准星位可手工调整；关联模式与时间模式的显示位置如果不同，应说明哪个是“星表位置”，另一个是布局结果。视角移动、屏幕投影都不产生新身份。
3. 本站穹顶若继续使用方位/仰角，展示如“梦境星位：方位 215°，仰角 47°”，或简码 `A215.0 H47.0`。这是本站坐标，不能换标签就变成真实 RA/Dec。若未来确实定义独立全天球，可用经度/纬度式刻度，并注明本站参考系；这一步不是本次必须项。
4. 若强烈想要 `HHMMSS+DDMMSS` 的美感，把它设为次级“梦境星位码”，用本站自定义前缀（如 D）而非带有科学含义的 J。精度明确、同位置允许多文并按星表号消歧。主编号仍是填写、关联和永久查找的入口。星位调整时优先更新当前地址；只有确实将旧星位码当已发布别名，才保留它到原文章的映射。
5. 现实参照星是选填注记：作者可以选 Vega、Sirius、某颗 Gaia 源作灵感，显示真实星名、完整 designation、来源坐标与星等，让读者打开一手星表或观测图。它不要求搬动本站文章星，不强迫“每文配一颗真实星”，也不限制一个真实星启发多篇文章。

## 四种候选方案对照

| 方案 | 实用性与趣味 | 限制 | 判断 |
| --- | --- | --- | --- |
| `SLD 0042` 私人星表序号 + 独立星位 | 极易输入，稳定；贴合真实星表登记和别名机制 | 序号本身不包含出生时间 | 推荐默认；时间与坐标在资料卡补足 |
| `SLD 20261011-01` 日期 + 同日序号 | 日期直观、便于年档案；更像一次“入册观测” | 长一些；必须冻结登记日期，与后来修正的发布日期分离；同日序号不是自然唯一 | 若作者特别看重“每颗星的诞生日”，可作主号候选或时间别名 |
| `SLD DHHMMSS+DDMMSS` 坐标型 | 天文观感强，能从标识读出本站位置 | 难输入、易混淆；改位置与标识冻结冲突；必须约定虚构参考系与碰撞规则 | 推荐次级星位码，不作为必填唯一身份 |
| 直接绑定真实星名/真实坐标 | 最容易接入真实资料、星座、星等彩蛋 | 真实天空位置并不服从博客关联与时间布局；多文可能选同一星；真实星位受历元与自行约束 | 推荐可选参照关系，首轮不做全站映射 |

不推荐将“日期 + 坐标 + 随机码”混成一个冗长 ID。它增加填写成本，却仍需单独的查重与持久身份规则。MJD 是可选观测日期注记，不是替代这些规则的魔法编码。

### 冻结日期方案可以同样稳定

`LD-20251020-01` 并不天然不稳定。若作者更喜欢“星的诞生”叙事，它可作为正式候选：日期取首次发表日，发行后冻结；`01` 是同日文章的追加式登记序号；补入同日旧文使用尚未分配的新号，不按日期或文件顺序重排既有编号；后续修正发布日期不修改号。资料卡可以明确区分“初次发表日 / 登记号中的日期”和“修订后的显示日期”。旧文章只有日精度也足够生成日期号，无需伪造小时分钟。

短号仍更适合当前个人博客：观测面板本来就展示年份/月日，右侧索引又预留较小的数字位置；日期号主要增加叙事信息，检索没有明显独占优势。`LD-0001` 更容易记住、说出和填写，出生日期、JD/MJD 则在星表卡中解释。这个判断是产品取舍，不是天文学规定；若作者更重视出生日期的仪式感，日期号也可采用。

### JD、J2000 和“发布时间”是三件不同的事

- `JD` 是一个时刻的连续日数表示；采用什么时间尺度须另行声明。它不是星名，也不是角度，单靠它不保证两篇文章不同号。`MJD` 也只是 `JD − 2400000.5`，不是加了一层身份保证。
- `J2000.0` 是天文学中的参考年/时刻表达，在旧赤道参考系统中还涉及分点；位置型 `JHHMMSS+DDMMSS` 中的 J 与这一参考系统约定有关，不能改成博客文章的“发表年份”。
- `HHMMSS` 出现在真实坐标型 designation 时表示赤经的时角单位；它不是作者文章发表的墙上钟时间。将北京时间 20:00 写为赤经 20h 只是自定义映射，必须明说是本站规则，并不会因此对应现实某颗星。
- 提示生日彩蛋时，如果文章只记录了 `2025-10-20`，应显示日精度的记事或只给日期转换示例；若需要单一 JD 值，可选一个明确写出的参考时刻并标明“按当日北京时间 00:00 约定换算”，不要把它暗示成真实发表瞬间或精确观测时间。首轮可直接不显示 JD。

## 索引与输入建议（设计推导）

搜索可接受 `SLD 42`、`0042`、标题/选填别名、原有内部 ID/旧地址，以及日期。编号精确命中时只列对应文章；坐标查询应给附近文章列表（类似 SIMBAD 的圆域查询），避免把低精度坐标错误地当成精确一对一键。点击索引标题直接阅读，继续尊重当前 2026-10-10 的交互决定；“定位星位”可成为另外的轻量动作，避免让编号检索多一道必经步骤。

这套方案把天文彩蛋放在“星表卡”中：私有 designation、本站星位、入册时间/可选 MJD、可选现实参照星。每个字段都有明确职责，作者日常写文不需要人工计算天文坐标。

## 检索边界

- 仅使用官方 IAU、ESA/Gaia、NASA、USNO、CDS/SIMBAD、SDSS、IPAC/2MASS 与官方 TNS 来源；没有使用商业“买星星命名”网站或二手科普作为命名规范依据。
- CDS 当前命名规范页面 `https://cds.unistra.fr/Dic/iau-spec.html` 因站点 robots 规则未能读取；用 IAU 正式历史规范、2MASS 与 SDSS 官方应用例子交叉核实。没有把未读取内容当已验证事实。
- 本研究不决定具体前缀和字段、不迁移文章、不改变星位、不改变链接；这些仍待作者讨论。
